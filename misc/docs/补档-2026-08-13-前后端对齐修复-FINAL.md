# 补档 2026-08-13 · 前后端对齐 + 致命Bug修复

> 背景：批次7交付后，前端才补完（Batch 7之后新建的 17 个 Vue 页面），发现前端 API 调用路径与后端 Controller 大面积不对齐，同时存在两个**启动即崩溃的致命级 Bean/URL 冲突**。本次补档统一修复，并留档避免下次重踩。

## 一、🔴 致命级（Spring Boot 启动直接崩）

### 1. 两个 `ChecklistController` Bean 同名 + URL 双冲突
| 问题 | 修复 |
|---|---|
| `content.controller.ChecklistController` 和 `incentive.controller.ChecklistController` 类名一致 → Spring 抛 `ConflictingBeanDefinitionException` | 后者重命名为 **`IncentiveChecklistController`** |
| 两个类都挂 `@RequestMapping("/checklists")` → Ambiguous mapping | 后者映射改为 **`/incentive-checklists`**，与前端 `checklistApi.tickIncentive/createCustom/removeCustom` 对齐 |

**文件变更**：
- 删除 ❌ `src/main/java/com/xindong/incentive/controller/ChecklistController.java`
- 新增 ✅ `src/main/java/com/xindong/incentive/controller/IncentiveChecklistController.java`

---

### 2. `LetterController` + `LoveLetterController` 同挂 `/letters` URL
| 问题 | 修复 |
|---|---|
| 空壳 `LetterController`（无 Service 依赖，只有 DTO） 和 有真实业务逻辑 + `LoveLetterService` 的 `LoveLetterController` 同时占用 `@RequestMapping("/letters")` → 启动 Ambiguous mapping | 删除空壳类，只保留业务版 `LoveLetterController` |
| 原来的 `LoveLetterController.create()` 用 `@RequestParam` 收参，前端 `letterApi.send()` 传的是 JSON body `{title,body,isCapsule,...}` → 400 参数缺失 | 改成 `@RequestBody LetterCreateReq`，与前端 DTO 字段逐字对齐 |
| 缺 3 个前端调用的接口：`PUT /{id}/cancel-schedule`、`PUT /{id}/mark-read`、`POST /{id}/reply` | 在 `LoveLetterController` 补全 |

**文件变更**：
- 删除 ❌ `src/main/java/com/xindong/content/controller/LetterController.java`
- 重写 ✅ `src/main/java/com/xindong/content/controller/LoveLetterController.java`（补 3 接口 + 改 body 收参）
