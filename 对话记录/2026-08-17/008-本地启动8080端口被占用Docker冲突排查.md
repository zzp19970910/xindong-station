# 对话记录 2026-08-17 / 008

## 一、原始问题

用户本地启动SpringBoot项目报错：`Web server failed to start. Port 8080 was already in use`，问是什么原因。

报错完整内容：
```
***************************
APPLICATION FAILED TO START
***************************
Description:
Web server failed to start. Port 8080 was already in use.
Action:
Identify and stop the process that's listening on port 8080 or configure this application to listen on another port.
```

## 二、思考过程

### 维度1：用户意图（想解决什么）
用户本地开发调试项目，启动时报端口被占，想知道原因+快速解决办法，能继续开发。

### 维度2：用户技术水平（对应写法深浅）
会用PowerShell执行命令，能看懂netstat输出，给具体命令+两种方案选择就行。

### 维度3：需求隐含约束
- 不能让用户等太久，要最快能解决的方案
- Docker Desktop占用8080是Windows上非常常见的坑，用户可能不知道
- 用户可能Docker里还有正在跑的容器（比如MySQL等），不能随便让他杀Docker进程

### 维度4：历史上下文
之前一直在聊Render公网部署，刚改完PostgreSQL适配的代码，用户可能切回本地想验证代码能不能跑，结果启动失败。

### 维度5：边界/歧义点（主动假设/追问）
需要先让用户查具体是哪个进程占了8080，不能直接猜。先让执行netstat，看到PID后再查tasklist确认程序名。

## 三、最终回答

分两步指导：

### 第一步：查占用进程
让用户执行 `netstat -ano | findstr :8080`，用户输出显示：
- LISTENING PID=12920（真正占8080端口的进程）
- 其他一堆SYN_SENT/ESTABLISHED都是出站连接，不用管

### 第二步：确认程序名
执行 `tasklist /FI "PID eq 12920"`，结果是：**`com.docker.backend.exe`** — Docker Desktop后台进程，不是Java。

### 给出3套解决方案（按推荐顺序）：
1. **方案1（10秒搞定）**：本地改端口，`application-dev.yml` 加 `server.port: 8081`，访问改localhost:8081
2. **方案2**：杀Docker进程 `taskkill /F /PID 12920`（但警告：如果Docker里有跑的容器别用）
3. **方案3（永久）**：Docker Desktop设置→Resources→Network，把HTTP代理端口从8080改成别的

推荐方案1，不用动Docker。

## 四、命令行执行

| 步骤 | 命令 | 执行结果 |
|------|------|---------|
| 1 | `netstat -ano \| findstr :8080` | 用户贴的输出：LISTENING 12920 |
| 2 | `tasklist /FI "PID eq 12920"` | 确认是 com.docker.backend.exe 12920 内存73MB |

## 五、补充说明

Docker Desktop新版（4.x之后）默认会占用8080端口做内部反向代理/扩展市场的HTTP代理，Windows上碰到率极高。
本地开发碰到8080被占，90%以上是这三个原因：
1. com.docker.backend.exe（Docker Desktop）
2. java.exe（之前的SpringBoot没正常关掉）
3. nginx.exe（本地装了Nginx）

碰到先查PID再杀或改端口，别直接硬来。
